# HHOF Goalie Sim — Goal Detector

Camera-based goal detection for the Hockey Hall of Fame goalie simulator.
Single-process-per-net architecture. Connects to a Node WebSocket server to
emit goal events and receive shot-incoming notifications.

---


## Production deployment (Windows)

Run `install.ps1` as Administrator. It:

1. Installs **uv** (Python package manager), **NSSM**, and **Node.js** via winget if not present
2. Runs `uv sync` to install Python deps, then restores `pip` into the venv (arena_api needs it at import time)
3. Walks through Lucid Arena SDK setup if using a GigE camera
4. Registers two Windows services via NSSM:
   - `goal-detector-N` — the Python detector
   - `goal-detector-admin-N` — the Node admin panel (always on, survives reboots)
5. Registers two scheduled tasks:
   - `hhof-calibrate-N` — runs calibration as the current interactive user (so OpenCV windows appear on screen)
   - `hhof-log-cleanup-N` — weekly Sunday 3am, deletes rotated log files older than 30 days

The installer prompts for:
- WebSocket server URL (where the Node game server is)
- Net number (1, 2, …) — service names are auto-generated from this

Services auto-start on boot. Logs go to `logs/` in the repo root (NSSM rotates at 10 MB).

### Admin panel

Once installed, open **http://localhost:8090** in any browser on the machine.

The admin panel shows live detector stats (FPS, mode, armed state, track count)
and provides:
- **Config editor** — edit any config.json value and save. Fields marked
  `[restart]` take effect after a service restart.
- **Restart detector service** — immediately restarts the NSSM service.
- **Run calibration** — stops the service, runs the 4-step calibration GUI on the
  local monitor (via the scheduled task, which runs as the interactive user so
  OpenCV windows appear on screen), then restarts the service automatically.

The admin panel connects to the detector via its own WebSocket on port 8766
(separate from the game server connection on 8765).

### Useful service commands

```powershell
nssm status goal-detector-1
nssm restart goal-detector-1
nssm stop goal-detector-1
nssm start goal-detector-1
nssm remove goal-detector-1 confirm

nssm status goal-detector-admin-1
nssm restart goal-detector-admin-1

Get-Content ".\logs\stdout.log" -Tail 50
Get-Content ".\logs\admin-stdout.log" -Tail 50
```

## Calibration

`--calibrate` opens a 4-step interactive GUI. Run it via the admin panel button
(production) or directly on a machine with a monitor (dev).

1. **Capture frame** — point camera, press `SPACE`.
2. **Goal line** — click left post, then right post. `ENTER` to accept, `R` to reset.
3. **Net interior** — click 4+ vertices of the inside of the net. `ENTER` / `R`.
4. **Approach zone** — click 4+ vertices of the area in front of the goal. `ENTER` / `R`.

Results saved to `config.json`. Re-run any time the camera moves or lighting
changes substantially.

The approach zone is required so the tracker sees the puck before it crosses the
line — without it the first detection is already past the line and the goal is
missed. If `approach_roi` is absent (old config), the detector falls back to
auto-mirroring the net polygon and logs a reminder.

## Operating modes

- **Armed (default):** scores goals only during a window after receiving
  `shot_incoming`. Emits `no_goal` when the window expires. For integration with
  the Node game logic.
- **Always on:** scores any line-crossing at any time. For testing/demos.

Toggle via the receiver dashboard, the admin panel, or send
`{"type": "set_mode", "mode": "always_on"}` over WebSocket. Set
`always_on_default` in config to choose the boot mode.

## Configuration reference

All settings live in `config.json`. Defaults shown; every field is optional —
missing keys fall back to defaults in the code.

### Identity & connection

| Key | Default | Description |
|---|---|---|
| `net_id` | `"net_1"` | Identifier for this net. Sent in every WebSocket message. |
| `server_url` | `"ws://localhost:8765"` | Game WebSocket server to connect to. |
| `admin_server_url` | `"ws://localhost:8766"` | Local admin panel WebSocket. Set to `null` to disable (not recommended — breaks the admin panel). Do not edit via the admin panel config editor; set directly in config.json if needed. |

### Camera

| Key | Default | Description |
|---|---|---|
| `source` | `0` | Camera index or video file path. Ignored for Lucid GigE. |
| `frame_width` | `1280` | Capture resolution. |
| `frame_height` | `720` | |
| `target_fps` | `120` | Requested framerate. Check startup log to confirm. |
| `capture_backend` | `"auto"` | OpenCV capture backend. Use `"lucid"` for Lucid GigE cameras. |
| `auto_exposure` | `true` | Let camera control exposure. Set `false` to use `manual_exposure` or `lucid_exposure_us`. |
| `manual_exposure` | `-7` | OpenCV backends only: log2(seconds). `-7` ≈ 1/128s. |
| `lucid_exposure_us` | `7800` | Lucid backend: exposure in microseconds. 7800 ≈ 1/128s. |
| `lucid_serial` | `null` | Lucid backend: serial number printed on the camera body. **Required when more than one Lucid camera is on the same GigE network** — without this the detector opens whatever camera is listed first, which is non-deterministic. Leave null for single-camera setups. |
| `lucid_sdk_path` | `null` | Override default Arena SDK install path. Only needed for non-default install locations. |

### Calibration data (set by `--calibrate`, do not hand-edit)

| Key | Default | Description |
|---|---|---|
| `goal_line` | `null` | `[[x1,y1],[x2,y2]]` — goal line endpoints. |
| `net_roi` | `null` | `[[x,y], …]` — net interior polygon. |
| `approach_roi` | `null` | `[[x,y], …]` — approach zone polygon. |

### Detection method

| Key | Default | Description |
|---|---|---|
| `detection_method` | `"motion"` | `"motion"` (MOG2 only), `"dark"` (brightness only), `"combined"` (both). Combined is best for dark pucks where shadow noise causes false positives. |

### Detection tuning

| Key | Default | Description |
|---|---|---|
| `bg_history` | `300` | MOG2 background model history length in frames. |
| `bg_var_threshold` | `30` | MOG2 sensitivity. Raise to reduce noise/shadow false positives. |
| `detect_shadows` | `true` | MOG2 shadow classification (shadow pixels = 127, below `fg_threshold`). |
| `fg_threshold` | `200` | Foreground mask threshold. Set >127 to exclude shadows. |
| `dark_threshold` | `60` | Brightness cutoff for `"dark"` and `"combined"` methods. Lower = stricter. |
| `puck_min_area` | `80` | Min contour area in full-res pixels. Tune with `verbose_contour_logging`. |
| `puck_max_area` | `4000` | Max contour area. Raise if motion-blur streaks are being missed. |
| `process_scale` | `0.5` | CV pipeline downscale factor. `0.5` = 4x faster at 640×360. |
| `morph_close_size` | `13` | Kernel for merging puck fragments (odd). Sized for processed image. |
| `morph_open_size` | `3` | Kernel for removing speckle (odd). Keep small. |

### Tracking

| Key | Default | Description |
|---|---|---|
| `min_track_hits` | `2` | Detections needed before a track can score. |
| `tracker_max_dist_px` | `250` | Max pixel jump between frames for track matching. |
| `tracker_max_age_s` | `0.4` | Track lifetime without a detection hit. |

### Goal logic

| Key | Default | Description |
|---|---|---|
| `armed_window_seconds` | `2.0` | How long after `shot_incoming` to look for goals. |
| `goal_cooldown_seconds` | `0.5` | Minimum gap between consecutive goal events. |
| `always_on_default` | `false` | Boot mode: `false` = armed, `true` = always-on. |
| `log_level` | `"INFO"` | Python log level: `"DEBUG"`, `"INFO"`, `"WARNING"`, `"ERROR"`. |

### Debug display

| Key | Default | Description |
|---|---|---|
| `debug_display_scale` | `0.5` | Scale of `--debug` windows. Windows are resizable; this sets initial size. |
| `debug_goal_flash_seconds` | `0.5` | Duration of the green GOAL banner on the debug overlay. |

### Verbose diagnostic logging

| Key | Default | Description |
|---|---|---|
| `verbose_contour_logging` | `false` | Log every accepted contour and near-misses. Turn on temporarily to tune area thresholds. |
| `verbose_contour_log_margin` | `0.5` | Fraction of thresholds used to define "near-miss". |
| `verbose_log_throttle_hz` | `5` | Max log lines/second to avoid flooding the console. |

## Wire format (WebSocket)

All messages are JSON. The detector connects out as a client to both the game
server and the admin server.

### Outbound (detector → server)

```json
{ "type": "hello",     "net_id": "net_1", "ts": 1730000000.123 }
{ "type": "heartbeat", "net_id": "net_1", "ts": 0,
  "fps": 119.2, "mode": "armed", "armed": false, "tracks": 0 }
{ "type": "goal",      "net_id": "net_1", "ts": 0,
  "track_id": 17, "speed_px_s": 1240.5,
  "shot_id": "shot_1730000000123", "mode": "armed" }
{ "type": "no_goal",   "net_id": "net_1", "ts": 0,
  "shot_id": "shot_1730000000123", "reason": "window_expired" }
```

### Inbound (server → detector)

```json
{ "type": "shot_incoming", "shot_id": "shot_1730000000123" }
{ "type": "set_mode",      "mode": "always_on" }
```

## Lucid Vision GigE camera (PHX004S)

Set `capture_backend: "lucid"` in `config.json`.

### One-time setup

1. **Install Arena SDK** — download from Lucid's downloads hub (Windows installer)
2. **Install Python wrapper** — handled by `install.ps1`; not on PyPI, installed from the `.whl` bundled with the SDK
3. **Assign camera IP** — use `IpConfigUtility` (bundled with Arena SDK) to give the camera a static IP on the same subnet as your GigE NIC
4. **Enable jumbo frames** — set MTU 9000 on the GigE NIC (Device Manager → adapter properties → Advanced → Jumbo Packet)
5. **Set resolution** — PHX004S native is 720×540; set `frame_width: 720` and `frame_height: 540`

### Multi-camera setup

If two cameras are on the same GigE network (e.g. net_1 and net_2), each
detector **must** have `lucid_serial` set to its camera's serial number
(printed on the camera body). Without it, both detectors open whichever
camera the Arena SDK lists first, which is non-deterministic.

The detector logs all discovered cameras at startup:

```
Found 2 Lucid device(s): PHX004S-M serial=2310001 ip=192.168.1.101, PHX004S-M serial=2310002 ip=192.168.1.102
```

Use those serials to populate each net's config.json. The field is also
editable in the admin panel under Camera → Lucid serial number.

### Known Lucid gotchas

- `arena_api` runs `pip show arena_api` at import time to get its own version. If `pip` is not in the venv (uv sync strips it), the import fails. `install.ps1` restores pip explicitly after `uv sync`.
- `AcquisitionFrameRateEnable` must be set `True` explicitly before setting `AcquisitionFrameRate` — otherwise the camera ignores `target_fps` and runs at its hardware maximum (~284fps for the PHX004S).
- Two detector instances cannot share a camera. A Windows named mutex prevents a second instance from starting — the service manager gets an `ERROR_ALREADY_EXISTS` and the new process exits cleanly before trying to open the camera.

## Tuning guide

### False negatives (puck not detected as a goal)

1. Run `--debug` and watch the foreground mask. Is the puck visible?
2. Enable `verbose_contour_logging: true`. Throw the puck. Did a contour appear?
   - "REJECT (below min)" with area close to `puck_min_area`: lower the min.
   - "REJECT (above max)" with area close to `puck_max_area`: raise the max.
   - No contour at all: MOG2 or dark threshold isn't seeing the puck. Try `"combined"` detection or adjust `dark_threshold`.
   - Contour ACCEPT but no goal: track didn't accumulate `min_track_hits`, or the puck's first detection was already past the line (approach zone too small — re-calibrate).

### False positives (goals when there shouldn't be)

1. Tighten `puck_min_area` / `puck_max_area` based on real puck readings.
2. Raise `bg_var_threshold` (MOG2 less sensitive).
3. Switch to `"combined"` detection (shadows must also be dark to count).
4. Raise `min_track_hits`.

## Known issues and gotchas

- **Windows 60fps USB cap:** Windows 11 24H2+ silently caps USB cameras at 60fps via the Modern Effects Pipeline. Disable per-camera in Settings → Bluetooth & devices → Cameras → "Basic camera mode". Not applicable for GigE.
- **NSSM SERVICE_PAUSED bug:** NSSM 2.24 (winget) has a race condition on Windows 11 where a service gets stuck in `SERVICE_PAUSED` if it exits quickly multiple times in a row. Workaround: `sc.exe start goal-detector-1` directly, or kill orphaned python.exe processes first.
- **Admin panel calibration requires a logged-in user:** calibration runs as the interactive user via a scheduled task — it will silently not show a window if no user is logged in at the time.
- **Approach zone fallback:** if the debug overlay shows a mirrored (auto-computed) approach zone rather than the one you drew, re-run `--calibrate` and complete step 4.
